## Root cause (the incident this fixes)

Switchdrive was syncing the **live `.git/` directory** across two computers. A
file-level syncer cannot merge git's binary, lock-sensitive index, so when both
machines wrote to `.git/` independently it overlaid one machine's state onto the
other and **corrupted the index** — phantom staged renames (e.g.
`Full_paper_canonical.md → CFP_FullPaper_v1.md`) and ~13 files reported "modified"
that were byte-identical to HEAD. Worse, the only copy of the June-19 edits lived in
**gitignored `.docx` files git never tracked**, so they were nearly lost.

**One-line rule: never let any file-syncer (Switchdrive / Dropbox / OneDrive /
iCloud) touch a live `.git/` directory.**

The two timelines that diverged: this machine advanced the paper to **v1.24** (14 Jun,
committed) while the parallel laptop forked at **v1.14** (12 Jun) and made uncommitted
Word edits on 19 Jun that were never committed.

## Decision

Adopt the user's own instinct: **split the single project into two sibling Git repos**,
both on GitHub, both cloned **outside** any synced folder.

| Repo | Visibility | Contents |
|------|-----------|----------|
| **`JPEP`** (existing) | public | `transparency/` audit trail + `Paper/MDversion/` markdown. Remote: `https://github.com/MicheleLoi/JPEP.git` |
| **`JPEP-private`** (new) | private (GitHub private repo, free) | everything currently gitignored: `Paper/journal/`, `Paper/arXiv/`, `_pipeline/`, the build/derive scripts (`build_paper.py`, `derive_distributions.py`, `check_references.py`, `renumber_sections.py`, `_run_caption.py`), `06_conversations/`, `conversations/`, `build/` |

**Sibling folders, NOT nested** — never put one repo's `.git/` inside another's working
tree. Scripts that span both sides reference the public repo via `../JPEP/...` relative
paths, which resolve identically on Windows and macOS when both repos live under one
parent (e.g. `~/Projects/` or `C:\Users\loimi\Projects\`).

**Why this over the alternatives** (evaluated by the Sonnet agent):
- *Single repo + filtered `git subtree` push to the public remote* — rejected: leaks
  private operational history (version numbers, revision decisions) into the public
  audit-trail repo's commit messages; fragile push step.
- *Keep one public repo, sync only binary outputs via a small Switchdrive folder* —
  acceptable minimal fix, but gives no version history for private content; the
  near-loss could recur (minus the index corruption).
- *git-crypt encrypted paths in the public repo* — rejected: GPG key management across
  Windows+macOS is heavy for a solo academic; free private repos make it unnecessary.

## Guardrails (so it can't recur)

1. **Never sync a `.git/` via a file-syncer.** Repos live under `~/Projects` /
   `C:\Users\loimi\Projects`, never inside Switchdrive.
2. **Commit + push BOTH repos before switching machines.** Make a `save-work` alias that
   runs `git add -A && git commit -m "checkpoint" && git push` in each repo. Git is now
   the sync mechanism for *everything that matters*, including the `.docx`.
3. **Corruption signature = phantom "modified" files identical to HEAD.** If `git status`
   shows changes you know you didn't make: `git fetch` then, after confirming the remote
   is current, `git reset --hard origin/main`. Run `git fsck` if you suspect object
   damage; if it errors, restore from the remote rather than committing.
4. *(Optional)* a `pre-push` hook that warns on unstaged changes.
